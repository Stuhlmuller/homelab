# Policy Bot

Policy Bot runs as the homelab GitHub App policy evaluator. It has no persistent
volume; all runtime credentials come from AWS SSM Parameter Store through
External Secrets and are rendered into `/secrets/policy-bot.yml`.

The Deployment runs one replica after the GitHub-App-owned SSM placeholders are
replaced. Keep `replicas: 1` or higher so the policy evaluator and webhook
receiver stay online. If credentials need to be revoked or rebuilt, scale this
file path back to `replicas: 0` in git before Argo CD rolls out placeholder
config.

Policy Bot looks for a repository-local `.policy.yml` first and falls back to
`policy.yml` in the shared `.github` repository. The homelab policy approves
PRs without a maintainer comment or review. The `main` ruleset requires Policy
Bot and CI checks to pass before merge.

## Routes

- Private operator UI, details, assets and OAuth:
  `https://policy-bot.stinkyboi.com` through Tailscale and Traefik.
- Public GitHub webhook:
  `https://policy-bot-hook.tail67beb.ts.net/api/github/hook` through Funnel.

Traefik and the retained Cloudflare route expose only the exact
`/api/github/hook` callback path. Policy Bot retains GitHub HMAC verification;
its UI and callback root stay private or denied.
After Funnel readiness, preview `python3 -I scripts/policy-bot-webhook.py`, then
follow the [guarded callback cutover](../traefik/CUTOVER.md) from clean reviewed
main. The helper changes only the fixed GitHub App webhook URL, preserving its
secret. Require a fresh successful signed delivery before retiring the previous
`policy-bot-hook.stinkyboi.com` Tunnel route. Source changes alone do not move
that external registration.

## Secrets

`IaC/live/aws-ssm-parameters` owns the expected SSM parameters:

- `/homelab/policy-bot/github-app/integration-id`
- `/homelab/policy-bot/github-app/webhook-secret`
- `/homelab/policy-bot/github-app/private-key`
- `/homelab/policy-bot/oauth/client-id`
- `/homelab/policy-bot/oauth/client-secret`
- `/homelab/policy-bot/sessions-key`

Replace the GitHub App ID, private key, OAuth client ID, and OAuth client secret
with the values from the GitHub App. Policy Bot names the App ID field
`integration_id`; this must be the GitHub App ID from the app's general
settings page, not the installation ID or OAuth client ID. The webhook secret
and sessions key are generated by Terragrunt; copy the generated webhook secret
into the GitHub App webhook settings before expecting deliveries to validate.

If the pod logs show `failed to get configured GitHub app` with
`404 Integration not found` from `https://api.github.com/app`, GitHub rejected
the configured app identity. Re-check that
`/homelab/policy-bot/github-app/integration-id` contains the GitHub App ID and
that `/homelab/policy-bot/github-app/private-key` is a private key generated
from the same GitHub App. This ExternalSecret uses `refreshPolicy: OnChange`,
so after fixing SSM, make a repo-owned metadata change to
`externalsecret.yaml` and sync through Argo CD so the Kubernetes Secret is
rendered again.

## Validation

```sh
kubectl kustomize clusters/homelab/apps/policy-bot
kubectl -n automation get deploy/policy-bot svc/policy-bot \
  virtualservice/policy-bot-octelium \
  virtualservice/policy-bot-webhook-octelium externalsecret/policy-bot-config
kubectl -n traefik get deployment/traefik service/traefik-private
kubectl -n traefik get ingress
curl -I https://policy-bot.stinkyboi.com/
curl -I https://policy-bot.stinkyboi.com/details/example/example/1
curl -sS -D - -o /dev/null https://policy-bot-hook.tail67beb.ts.net/api/github/hook
curl -sS -D - -o /dev/null https://policy-bot-hook.tail67beb.ts.net/
```

Expected workload behavior: the Deployment has one available replica. Expected
route behavior: the internal host serves the normal Policy Bot UI paths, the
details URL redirects to `/api/github/auth`, and an unsigned GET to the public
hook returns `404` with one `X-Request-ID` from the application. The callback
root returns `404` without that header. Policy Bot 1.41.2 registers a
[POST-only webhook route](https://github.com/palantir/policy-bot/blob/v1.41.2/server/server.go#L226-L227);
its [baseapp middleware](https://github.com/palantir/go-baseapp/blob/v0.7.0/baseapp/middleware.go#L38-L46)
adds the request ID even when a method has no matching route. GET does not test
HMAC validation. Require a fresh successful GitHub delivery after callback
cutover; never trigger a webhook just to test ingress.

On October 10, 2026, strict-TLS GETs through both the private mesh and public
Funnel reached that backend 404, with request IDs confirmed in Policy Bot logs.
The Funnel root had no backend header. This establishes read-only routing,
not successful callback delivery. See the [staged cutover](../traefik/CUTOVER.md).

## Rollback

Revert a failed application revision through GitOps while preserving its working
Funnel callback registration. If Funnel cannot reach Policy Bot but the retained
Cloudflare/Octelium callback still reaches its hook, the reviewed
`codex/policy-bot-webhook-rollback` PR contains a fixed emergency runner. It is
for an explicit one-time user-approved exception while the required Policy Bot
check cannot report; it does not bypass the normal helper's exact-main guard.
From a clean checkout of the signed PR head, use fresh full SHAs:

```sh
nix develop --command python3 -I scripts/policy-bot-webhook-emergency.py \
  --expected-main '<fresh-main-sha>' \
  --expected-head '<reviewed-pr-head-sha>' --rollback --execute
```

The runner verifies the open PR head, its GitHub-verified signature, and its
current-main base before touching credentials. The helper then preflights the
old hook and root through fixed public DNS and strict hostname-checked TLS,
patches only the fixed previous URL, reads
back the unchanged HMAC secret/settings, and saves a private rollback receipt.
It does not trigger an event. After the callback readback, run the separate
fixed [GitHub App redelivery](https://docs.github.com/en/rest/apps/webhooks#redeliver-a-delivery-for-an-app-webhook)
command from the same reviewed checkout with fresh main/head SHAs:

```sh
nix develop --command python3 -I scripts/policy-bot-webhook-emergency.py \
  --expected-main '<fresh-main-sha>' \
  --expected-head '<reviewed-pr-head-sha>' --redeliver --execute
```

It checks the rollback receipt, current old URL, and #1679's unchanged head.
It writes a private one-attempt receipt before the official POST for failed
`check_run` delivery `3850311852634406912` (#1679 Terragrunt Gate, HTTP 500).
If the POST response is uncertain, inspect deliveries read-only; do not retry
the command. Verify the exact redelivery from the clean signed checkout:

```sh
nix develop --command python3 -I scripts/policy-bot-webhook-emergency.py \
  --expected-head '<reviewed-pr-head-sha>' --verify
```

Verification requires the same GUID with a new delivery ID, matching event,
PR #1679 head and number, the old callback URL, HTTP `2xx`, and successful
`policy-bot: main` status on that head. It reports current main without
requiring the unmerged PR base to remain current. Keep the previous Tunnel
route until replacement acceptance. Preserve the App credentials and webhook
secret. Do not restore the deleted public DNS writer.
