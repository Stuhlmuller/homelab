# Validation Guide

Use the Nix development shell after its narrow Terragrunt pin is implemented. The four official release binaries must first match their published checksum manifest entries; Nix fixed hashes pin exactly those artifacts. These are validation commands, not recorded passing results.

```sh
nix develop --command terragrunt --version
nix develop --command tofu version
nix develop --command terragrunt hcl fmt --check
nix develop --command tofu fmt -check -recursive IaC/terragrunt-catalog/modules
nix develop --command python3 scripts/ci/state-encryption-test.py
nix develop --command python3 scripts/ci/terragrunt-stack-test.py
nix develop --command terragrunt --working-dir IaC stack generate
nix develop --command terragrunt hcl validate
nix develop --command bash scripts/ci/static-checks.sh
nix develop --command bash scripts/ci/conftest-policies.sh
git diff --check
```

Expected: Terragrunt v1.2.2; focused test separately captures actual production-root backend generation through a non-cloud CLI shim and confirms KMS key/region/metadata alias and both enforced targets. A standalone disposable PBKDF2 map generated by real Terragrunt proves old/new encrypted state and saved-plan readability with real OpenTofu and rejects missing alias/plaintext input; it is not derived by modifying the production root. Retirement regression confirms the unchanged backend path, shared policy inheritance and absence of duplicate policy. All relevant format/static/policy checks pass.

If Nix sandbox activation is unavailable, use an approved Nix invocation or verified matching temporary binaries and state the exact limitation. Do not claim helper Terragrunt v1.0.8 represents the new pin.

An authenticated affected-unit plan must use the repository's `scripts/ci/terragrunt-plan.sh` path and exact established credentials. Inspect secret-bearing/operator exclusions before claiming complete coverage. Missing credentials block that evidence, not offline validation. Do not download or overwrite live state for testing. Existing plaintext records must surface as a failed plan and a separately scoped migration need; do not enable fallback.

Before live encrypted writes, source and pin can be reverted together through normal delivery. For the eleven previously protected modules, preserved metadata identity supports readability in both directions. Newly protected units must retain equivalent encryption after their first ciphertext write until a separate migration is designed; a blanket source revert would otherwise remove the policy needed to read their ciphertext. A source revert is not a state restore and does not require copying an older state object over the current one.

In this cloud environment use `/workspace/cloud-tools/bin/nix develop --no-update-lock-file --no-write-lock-file --command ...` with approved escalated execution and login disabled; this is the existing Nix wrapper, not a second tool installation.
