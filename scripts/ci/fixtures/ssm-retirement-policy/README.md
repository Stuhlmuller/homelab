# Candidate policy for the four #805 SSM retirements

Conftest runs this fixture only when it receives this directory explicitly.
Regular Terragrunt plan and apply still use `policy/`, which denies SSM
deletes. A passing shape check authenticates neither the operator nor the
saved plan and cannot authorize replay.

The candidate accepts a complete OpenTofu 1.2-format plan whose only changes
remove the four root `aws_ssm_parameter.this` instances. It checks the prior
SecureString name, provider, state ID, and ARN in the homelab AWS account and
`us-west-2`. The four retired declarations already have
`reader_access = false`. An IAM change, resource drift, a replacement, an
output change, a missing deletion, or any other resource action fails the
shape check.

## Protected retirement lane

The ordinary SSM workflow generates its saved plan and applies it in the
same job. Its source checks and production environment do not currently bind
an authenticated owner's review to the generated bytes. A separate lane needs
the following executable stages before this candidate can be used in delivery.

1. Plan the fixed SSM unit at the exact reviewed current main revision, with
   normal state locking and the declared plan encryption. Keep the encrypted
   binary plan and the full JSON export private. A review packet contains only
   the four addresses, delete actions, expected region and account, revision,
   unit and backend identity, plan creation time, and the SHA-256 of the exact
   encrypted plan bytes. Export JSON directly from those bytes and run the
   candidate shape check before publishing the packet.
2. Bind the owner's authenticated approval to that exact packet and plan hash.
   Verify the approver and the structured tuple of repository, revision, unit,
   reviewed plan SHA-256, freshness and review identity. A digest entered by
   the runner, a generic PR review, and an environment approval received before
   the packet exists do not establish this binding. The repository has no
   configured signer/receipt path for this retirement.
3. Replay through a dedicated role and fixed unit with only the four named
   `ssm:DeleteParameter` ARNs and the narrowly necessary read, KMS and
   state-lock access. Recheck remote main, the approved receipt, the artifact's
   SHA-256 and plan shape before replay. Obtain the binary once and keep it in
   a private directory through validation and apply. Use the immutable saved
   plan with ordinary state locking and no replan. OpenTofu's stale-plan check
   supplies the state-lineage and serial guard under lock. Reject changed main,
   stale state, missing approval, digest mismatch, additional changes, or an
   expired receipt. Ordinary Terragrunt permissions and policy stay in place.
4. Confirm the four state addresses and SSM metadata records are absent.
   Preserve only a sanitized receipt and remove private plan files through the
   lane's cleanup path.

The existing CI policy keeps saved plans and their JSON exports off Actions
artifacts. Reuse a private operator-controlled handoff for the binary plan or
review a separately encrypted, access-controlled transfer before adopting a
hosted two-job lane. This fixture chooses neither transport nor approval
authority and creates no workflow, role, secret, or credential.

Run the candidate tests with
`conftest verify --policy scripts/ci/fixtures/ssm-retirement-policy`.

## Local packet verification fixture

`review_packet.py` implements the offline binding for a private operator
session. The packet identifies this retirement, the exact repository revision,
the fixed unit and backend, the four names, the approval window, and the
SHA-256 of the encrypted binary. The owner can sign its canonical bytes only
after reviewing the exact four-delete plan. The candidate verifies a detached
binary OpenPGP document signature with GnuPG and compares the resulting
signing key and primary fingerprints with independently enrolled values. The
fixture uses a one-hour packet validity window.

Use a protected source of trust for the exact signing fingerprint and the
current owner public keyring. The existing Harbor diagnostic key pin enables
encryption to its reviewed recipient. This retirement has no approved signing
subkey or keyring. Obtain the owner's authenticated authorization of the
specific signing key and how its public key is enrolled before wiring replay.

The candidate verifies the bytes passed to GnuPG, checks the packet against
the independently resolved remote main revision and clock, and copies the
encrypted plan into a private temporary directory while hashing it. Future
replay must run the shape check on the export from that same copy, immediately
recheck remote main and its hash, and hand that exact copy to the declared
Terragrunt apply in the fixed unit. The code exposes no apply entry point.
It verifies approval and byte identity. OpenTofu must enforce configured
encryption and state lock/serial checks when replay is implemented.

Run the seven offline verification tests in the repository's Nix shell with
`python3 -I scripts/ci/fixtures/ssm-retirement-policy/review_packet_test.py`.
The integration test creates a disposable OpenPGP signing subkey. No operator
key or live plan is needed.
